REOWN 개발 현황 및 팀 요청사항
기준일: 2026년 11월 21일
기준: 현재 로컬 저장소의 코드와 문서
팀 구성: 총 5명 — 백엔드 2명, 프론트엔드 2명, 데이터베이스 1명

현재는 인증·상품 조회/관리·거래 상태·채팅의 백엔드 코드가 구현됐고,
프론트 연동과 DB 준비가 남아 있는 상태입니다.

앞서 “구현 완료”라고 정리한 항목은 코드 작성 기준입니다.
현재는 환경변수가 없어 실제 DB를 연결한 통합 동작까지 확인하지 못했습니다.
아래의 “구현됨”은 실제 서비스 전체 동작 검증 완료를 의미하지 않습니다.


0. 5명 기준 역할 분담

백엔드 1은 본인, 백엔드 2는 JWT를 담당한 백엔드 협업자를 뜻합니다.
본인의 상품·거래 구현 및 TypeScript 전환 이력과 협업자의 JWT 담당 사실을 기준으로
정리했습니다. 아래의 추가 기능·프론트 세부 분담·배포 분담은 제안이며,
실제 기존 분담이 있다면 그 내용을 우선해 조정합니다.
현재 구현 여부와 새로 제안한 담당 범위는 별개이며, 구현 기여자를 바꾸는 의미가 아닙니다.

[백엔드 1 — 본인: 상품·이미지·거래]
- 상품 등록·조회·검색·수정·삭제 API.
- 카테고리·지역 조회 API.
- 이미지 업로드·조회·삭제·순서 변경 API와 Storage 연결 코드.
- 거래 예약·완료·취소 및 구매·판매 내역 조회 API.
- 후속 기능: 가격 제안·거래 약속 API.
- 백엔드 2와 서버 배포·공통 설정·통합 테스트 공동 수행.

[백엔드 2 — 협업자: 인증·회원·채팅·관심 기능]
- 회원가입·로그인·JWT 및 내 정보·프로필·지역 수정 API.
- 찜·장바구니 API.
- 채팅 REST API·Socket.IO 인증·메시지·읽음 처리.
- 후속 기능: 후기·알림·신고·차단 API.
- 백엔드 1과 서버 배포·공통 설정·통합 테스트 공동 수행.

[프론트엔드 1: 상품 탐색·판매 화면]
- 홈·상품 목록·상세를 예시 데이터에서 실제 상품 API로 교체.
- 검색·필터·정렬·페이지네이션·카테고리·지역 선택 연동.
- 상품 등록·수정·삭제·사진 업로드 화면 연결.
- 찜·장바구니 화면 연결.
- 프론트 배포 주담당. 프론트엔드 2와 공통 UI·API 클라이언트 조정.

[프론트엔드 2: 회원·채팅·거래 내역 화면]
- 회원가입·로그인·로그아웃·마이페이지·프로필 수정 연결.
- 채팅 목록·채팅방·실시간 메시지·읽음 처리 연결.
- 판매자의 예약·완료·취소 버튼, 구매·판매 내역 화면 연결.
- 후속 기능: 가격 제안·약속·후기·알림·신고·차단 화면.
- 문의·공지사항은 정적 유지 여부를 팀과 합의.
- 배포 환경의 Socket.IO 연결을 백엔드 2와 확인.

[데이터베이스 1: DB·초기 데이터·Storage 설정]
- PostgreSQL 접속 정보 제공 및 연결 가능 여부 확인.
- migration 검토·적용, 지역·카테고리 seed 준비·적용.
- 테스트 데이터 준비와 적용 상태 문서 갱신.
- Supabase Storage 버킷·공개 읽기 설정·서버용 접속 정보 관리.
- 스키마·버킷 설정은 DB 담당자가 관리하고, 업로드 API 코드는 백엔드 1이 구현.

인증·Storage·배포를 담당할 별도 인원을 추가하는 것이 아닙니다.
인증은 백엔드 2, Storage 설정은 DB 1, Storage 연동은 백엔드 1,
백엔드 배포는 백엔드 1·2, 프론트 배포는 프론트엔드 1·2가 나눠 맡는 제안입니다.

2. 현재 실행과 검증을 막는 문제

[최우선] 루트 .env 없음
- 증상: 백엔드 실행 시 JWT_SECRET 오류로 종료.
- 조치: 프로젝트 루트 .env에 DATABASE_URL, JWT_SECRET 설정.
- 경로: C:\git_Desktop\reown\.env
- 담당: 본인이 로컬 파일 설정. DATABASE_URL은 DB 1에게, JWT 설정 방침은 백엔드 2에게 확인.


[최우선] 인증 코드가 users.region_name 사용
- 조치: DB 담당자에게 002_add_user_region_name.sql 적용 여부 확인 요청.
- 중요: 실제 DB에 이 컬럼이 없으면 로그인과 회원가입 모두 실패할 수 있음.
- 회원가입에서 동네명을 입력하지 않아도 해당 컬럼을 조회하므로 확인이 필요함.
- 담당: DB 1이 적용 상태 확인·처리하고, 백엔드 2가 가입·로그인 검증.

[높음] 지역·카테고리 초기 데이터 준비
- 저장소에 지역 seed 파일이 없음.
- 카테고리 seed는 문서상 미적용.
- 조치: DB 담당자가 실제 적용 상태를 확인하고 데이터 준비.
- 담당: DB 1. 적용 후 백엔드 1과 프론트엔드 1에게 사용 가능한 ID 공유.

[높음] 예시 상품과 실제 DB 상품 분리
- 조치: 상품 목록·상세 API 연동.
- 예시 상품 ID로 실제 채팅을 시작하는 문제를 해소해야 함.
- 담당: 프론트엔드 1이 상품 API 연결, 백엔드 1·2와 프론트엔드 2가 채팅 진입 확인.

[높음] 배포 설정의 Socket.IO 연결
- 현재 배포 설정은 /api만 백엔드로 전달.
- 조치: Socket.IO 접속 주소·프록시 설정을 별도로 확인.
- 담당: 백엔드 2와 프론트엔드 2가 소켓 연결, 프론트엔드 1이 프론트 배포 설정 확인.

DB 작업 현황 문서:
- db/README.md
- 문서에는 002_add_user_region_name.sql이 미적용으로 기록돼 있음.
- 실제 원격 DB 상태를 조회한 결과는 아니므로 DB 담당자의 확인이 필요함.

5. 환경변수와 JWT 관련 정리

- 현재 서버 실행에 필수인 값: DATABASE_URL, JWT_SECRET.
- PORT 기본값: 4000.
- JWT 만료시간 기본값: 2h.
- Storage 키와 카카오 키는 현재 서버 시작 자체에는 필요하지 않음.
- JWT는 같은 백엔드 서버가 발급하고 검증하면 되므로 각자 로컬 서버에서는 다른 키 사용 가능.
- 공용 서버의 토큰을 로컬 서버에서도 검증해야 한다면 같은 키가 필요함.
- DB 접속 정보를 공유하기 어려운 경우 공용 개발 백엔드 주소와 테스트 계정을 받아
  프론트 연동을 진행하는 방법도 있음.
- 실제 비밀값은 GitHub·공개 문서에 적지 않고 팀에서 정한 안전한 별도 경로로 전달.
